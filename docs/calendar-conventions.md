# 農曆與時間慣例

## 自動模式

瀏覽器使用 `Intl.DateTimeFormat("zh-TW-u-ca-chinese")` 取得農曆年、月、日，時區使用 IANA 名稱。預設為 `Asia/Taipei`。若瀏覽器不支援 Chinese Calendar，程式停止自動換算並要求人工輸入。

中央氣象署 A-A0087-001 只用作固定邊界測試與節氣核對，不在 runtime 呼叫外部 API。

官方資料能支持國農曆日期、閏月與節氣核對，不能證明「立春換年」或任一子時換日規則是術數唯一正法；這些差異由 profile 明確記錄。

## Calendar profiles

### `taipei-lunar-new-year-v1`

- 時區：`Asia/Taipei`
- 年界：農曆正月初一
- 閏月：沿用同名月份數
- 換日：民用午夜

### `taipei-lichun-v1`

- 時區：`Asia/Taipei`
- 年界：立春交節時刻
- 預載中央氣象署 2023 至 2028 年固定立春時刻，版本為 `cwa-annual-calendar-2023-2028-v1`。
- 沒有固定資料的年份必須提供 `lichunInstantIso`，否則停止並要求人工確認。

### `taipei-late-zi-next-day-v1`

- 年界：農曆正月初一
- 23 時仍屬子時。
- 農曆日期在 23 時改用次日。

## 閏月

預設閏月沿用同名月份，例如閏二月仍以 2 入數。自訂 profile 可選 next-month-number，但結果必須保留設定，不能靜默變更。

## 手動模式

人工輸入優先於自動轉換。結果會標示：

- `mode = manual`
- 所選時區
- 年界
- 閏月規則
- 子時換日規則
- 人工輸入警告

## 固定測試點

- 2023-03-22：閏二月初一。
- 2025-12-20：農曆冬月初一。
- 2026-01-19：農曆臘月初一。
- 2026-02-17：農曆正月初一。
- 23 時：民用午夜與晚子時換日的差異測試。

### 2023 至 2028 立春邊界表

### 人工更新限制

- Runtime 不連線抓取中央氣象署資料；上述時刻是可重播的固定快照，不會自動延伸到 2029 年以後。
- 2028 年日曆由中央氣象署於 2026 年 2 月發布；立春精確時刻取自同月發布的 2027 年日曆第 2 頁次年節氣附表，並以 2028 年日期表交叉核對。未來年次資料仍會滾動檢核，故須定期重驗。
- 新年度資料發布後，必須人工核對官方年度日曆或 A-A0087-003，並一起更新 `lichunInstants`、來源清單、資料版本及逐年邊界測試。
- 不得用「通常是 2 月 4 日」推估缺少年份。查無固定資料時採 fail-closed：改用正月初一年界，或由使用者手動提供 `lichunInstantIso` 並自行負責版本依據。

曆法結果仍須依使用者採用的師承或約定核對，系統不宣稱所有術數流派共用同一慣例。
